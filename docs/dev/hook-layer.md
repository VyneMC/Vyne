# Patch layer

Vyne patches vanilla Minecraft itself (see [plan.md](../../plan.md)). The patch layer is everything Vyne changes in vanilla so that the NeoForge API and Fabric API can run on it. It is built by Vyne, shipped inside the Vyne jar as binary diffs, and applied to the player's own vanilla jar.

## How it is built

`./gradlew hookPatches` (part of `./gradlew build`):

1. Installs NeoForge's patched game for the client and the server, once per build machine (`NeoForgeInstall`, under `build/hook-inventory/`).
2. Builds vanilla Minecraft with Mojang names for each side (`VanillaGame`).
3. Diffs every changed class, vanilla against NeoForge's patched game, with jbsdiff (`HookPatches.write`), and writes `client.zip` and `server.zip` with one `.patch` per class plus an index of the expected vanilla SHA-1 per class.

The zips go into the Vyne jar at `META-INF/vyne/patches/`. For NeoForge 21.1.265: 1613 classes per side, about 4.5 MB (client) and 4.8 MB (server). Nothing decompiled and no Minecraft class is shipped: only diffs.

## How it runs

For a pack whose mods are all NeoForge mods, this is the default:

1. `VanillaGame` builds vanilla with Mojang names from the player's Minecraft jar and Mojang's mappings, cached.
2. `HookPatches.apply` checks each class against the index (a different Minecraft jar is refused with a clear message), applies the diffs and NeoForge's access rules, and caches the result under `.vyne/cache/hooked/`.
3. `NeoForgeLibraries` downloads the six libraries NeoForge needs (FML loader, event bus, jar handler, console), once.
4. Vyne's copy of the NeoForge API (`META-INF/vyne/neoforge.jar`) and the NeoForge mods go through the same exact rename as the game, and Vyne's own FML (`dev.stolym.vyne.fml`, wired in by `vyne/routing/neoforge-21.1.txt`) runs NeoForge's lifecycle.

`-Dvyne.hooks=false` uses NeoForge's installer at first start instead (the older "patched mode"); Vyne also falls back to it when the patches are missing from the jar. Packs that mix Fabric and NeoForge mods use the compatibility path until Phase 6.

Tested (2026-11-16): NeoForge-only servers with Mouse Tweaks, CraftPresence, UniLib and Comforts (blocks placed, items present) reach `Done` with 0 ERROR lines; clients with Mouse Tweaks, CraftPresence, UniLib and Skin Layers 3D reach the title screen.

## The hook surface

The structure NeoForge adds to vanilla: changed superclasses, added interfaces, fields and methods, widened access. It is data (`src/main/resources/vyne/hooks/neoforge-<version>/surface.tsv` and `accesstransformer.cfg`) generated by `./gradlew hookSurface`.

- `./gradlew minecraftHookedJar` applies it to vanilla with Mojang names, and Vyne's copy of the NeoForge API compiles against that jar.
- At runtime, `accesstransformer.cfg` widens access on the patched classes.

For NeoForge 21.1.265: 6 superclasses, 91 interfaces, 272 fields, 853 methods, 830 access changes.

## Fabric API on the patch layer (Phase 6)

NeoForge's patches change 211 vanilla methods that Fabric API's mixins also target (`data/hooks/overlap-*.tsv`, see [hook-inventory.md](hook-inventory.md)); those mixins fail on the patched classes. Because Vyne builds its own patches, the Fabric API event call is added into the patched method when the patches are built, next to NeoForge's hook, instead of being applied as a mixin at runtime. Fabric API's other mixins target code NeoForge does not change and stay as they are.

## Vyne's copy of the NeoForge API

`src/neoforge/` is NeoForge 21.1.265's API source and resources with NeoForge's LGPL-2.1 headers, compiled against `minecraftHooked` plus NeoForge's libraries (`gradle/neoforge.gradle`). Its jar manifest carries the NeoForge version, and Vyne's FML registers that version, so NeoForge reports 21.1.265.

## Updating NeoForge

Mods almost always declare a minimum NeoForge version (`[21.1.0,)`), so shipping the newest 21.1.x satisfies nearly every 1.21.1 mod.

Measured between NeoForge 21.1.233 and 21.1.265 (32 releases): 24 of 956 API source files changed and 4 were added (about 300 lines); 10 of 768 patched vanilla classes changed and 4 were added. An update is: set `hook_neoforge_version`, regenerate the inventory and the surface, merge NeoForge's API changes into Vyne's copy, and rebuild; `hookPatches` produces the new diffs.
